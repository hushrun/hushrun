# 0114. RSpec and Minitest

- **Status:** accepted
- **Date:** 2026-11-24
- **Rules:** C-82 to C-85; relies on C-30 to C-34, C-38 to C-40, ADR 0068, 0069, 0071, 0080, 0081,
  0083, 0085, RFC 0004

## Context

`hushrun init` already knows a Ruby project's tests as whole checks (`bundle exec rspec`,
`bundle exec rake test`, `bin/rails test`), and nothing below a check was reused: a change to one
model ran every spec file. Ruby has no compile step hushrun could reuse (a native gem extension is
built once, by `bundle install`, outside every check), so this is test reuse alone, and rules
B-180 to B-189, held for Ruby's build blocks, stay unused.

Ruby makes "what a test file read" harder than Python. A constant defined in a required file is
read with none of its code running; Rails' Zeitwerk and Ruby's own `autoload` load a file when a
constant is first named, from whichever test names it first; class bodies (`has_many`,
`validates`) run once, at load, and shape every later test; and Rails keeps fixtures and compiled
templates in memory after the first test reads them. An audit of what works today, on a gem with
RSpec 3.13, a Minitest project under Rake (Minitest 5.20 and 6.1) and a Rails 8.1 app on Ruby 3.3,
found nothing: every COMMAND went to the default adapter, which never starts.

## Decision

1. **Loading.** hushrun writes one Ruby file to `<cache dir>/adapters/ruby-<hash>/hushrun_ruby.rb`
   and sets `RUBYLIB` to that directory first and `RUBYOPT` to what it had then `-rhushrun_ruby`,
   so every Ruby process of COMMAND loads it, Bundler's and Rake's included, through a list that
   holds any path (a `-r` with an absolute path can't hold a space). It also sets
   `DISABLE_BOOTSNAP_COMPILE_CACHE=1` (Bootsnap's compile cache loads a file without Ruby compiling
   it, which watching needs) and `DISABLE_SPRING=1`. The file loads no gem and no library, its JSON
   included, so it never activates a gem before Bundler picks its version; it does nothing without
   a `hushrun.json`, on another engine than CRuby or below Ruby 3.1, and writes nothing in a process
   where neither RSpec nor Minitest loads.
2. **Which COMMANDs**: `rspec`, `rails test…` and `rails spec…`, `rake` with any tasks, and
   `ruby`, each by name or path (`bin/rspec`, `bin/rails`) and after `bundle exec`; `ruby -S
   <program>` is that program's. Not offered, said once: `rspec --dry-run`, `--bisect`,
   `--only-failures`, `--next-failure`, `--init`, `--version`, `--help`; Spring; a Ruby with
   `--disable=rubyopt`.
3. **Code that ran.** Each file of the repository Ruby compiles (TracePoint's `script_compiled`)
   gets a TracePoint for its own code (`enable(target: iseq)`, which covers the methods and blocks
   it defines), on `line`, `call` and `b_call`. Its first event in a **window** records the file
   for that window and disables it, so a file costs one event per window, and every file that fired
   is enabled again as a window opens or closes. Windows: a test file's loading; a test (RSpec's
   example with its hooks and `let`s; Minitest's test with `setup` and `teardown`); a group's run
   around its examples, or a Minitest class's around its tests (`before(:context)`), which is a
   shared setup for the tests that ran in it; and none, the session. A file of the repository is
   one under its root and outside an installed gem (`vendor/bundle`, `.bundle`, `gems/<name>-<v>/`).
4. **Requires are edges.** `require`, `require_relative` and `load` from a file of the repository
   add an edge from it to the file they name, also when it is loaded already; a test file read the
   files its windows and the session ran, opened and listed, and every file their edges reach, to
   the end. `require` and `load` are wrapped in `Kernel` as RubyGems, Zeitwerk and Bootsnap wrap
   them (an alias chain, never `prepend`, which a later `module_function` breaks), and so is the
   copy on `Kernel`'s singleton, which Ruby 3.3's `bundled_gems.rb` sends every require to; the
   frame that asked is the first above every wrapper's. `require_relative` is resolved as Ruby
   resolves it, from the asking frame's file, and required through the require Ruby had before
   RubyGems (a wrapper that called Ruby's own would resolve from this file).
5. **Ambient files.** A file of the repository loaded while a window is open, by code outside the
   repository (Rails' initializers), by an autoload (`Module#autoload`, which Zeitwerk calls, or a
   line that names no `require` or `load`), or opened by code with no file of the repository on its
   stack (Rails' fixtures, a template's first read), is read by that window and every window after
   it in the process: what it holds stays for later tests that never load or open it again. This is
   what makes a Rails app sound, and coarse: what one test autoloaded, every later one reads.
6. **Opens and listings**: `File.new` and `File.open` (through `File#initialize`), `IO.read`,
   `binread`, `readlines`, `foreach`, `Dir.glob`, `Dir[]`, `children`, `entries`, `each_child`,
   `foreach`, `empty?` and `Dir.new`. Every file of the repository on an open's stack gets an edge
   to the opened file, so a value a file read once and kept reaches every test that runs its code.
   A listing counts when the code that made it is a file of the repository (spec_helper's
   `Dir[...].each { require }`): the open window reads the directory, and an edge from that file
   reaches every test file that runs it. A listing a gem's code makes is no read: the runner
   finding its test files, Zeitwerk setting up autoloads for `app/` as Rails boots, Active Record
   finding `fixtures :all`. What a test uses of those it loads or opens, which is read; counting the
   listings made every test of a Rails app read every file of `app/`, and attributed them to
   whichever test file booted the app.
7. **Units and the unit rule.** A unit is a test file as the runner names it: RSpec's
   `files_to_run`; for Minitest, the file each test method is defined in. The unit rule is the list
   the run that wrote the map gave (ADR 0071's, as Jest's). A file whose loading no test file owns
   (spec_helper, the app's boot, a binstub run as the main script) is the session's: every test
   file reads it. A test file no test of which was selected, by hushrun or by the runner, says
   nothing.
8. **Selection.** Only the first process whose RSpec or Minitest starts claims the run's directory
   (`ruby-claim`). RSpec: as it announces its filters, each example `hushrun.json` lists gets
   `hushrun_reused` in its metadata and one exclusion filter leaves them out, so a group whose
   examples are all reused runs none of its hooks; RSpec prints the filter (`Run options: exclude
   {:hushrun_reused=>"already passed on the files it read"}`); a location or id on the command line
   overrides exclusions in its file, and the adapter reports what RSpec actually left out. Minitest:
   `runnable_methods` loses them. A test's **id** is RSpec's scoped id, `[1:2:1]`, as `rspec
   'spec/a_spec.rb[1:2:1]'` takes it, and Minitest's `Class#method`.
9. **Outcomes.** An RSpec example is skipped when it ends pending, failed when it ends otherwise but
   passed; an example a failing `before(:context)` failed without running is failed. A process that
   exits with a failure while no test of it failed (a `before(:suite)` or `after(:context)` that
   raised, a test file that didn't load) keeps no pass: its facts say `failuresByUnit: false`, with
   `notKept`.
10. **Processes.** A fork with no test running goes on observing in the child, which writes its own
    facts: Rails' parallel workers fork after the test files loaded, and the merge sums what each
    finished within the start. A fork inside a test makes the child write nothing, and the test
    `fork`, not followed. A subprocess (`system`, `spawn`, backticks, `IO.popen`, `Process.spawn`)
    is `subprocess`, not followed, for the window it ran in. A Ruby a test starts inherits
    `HUSHRUN_RUBY_START` and does nothing. Tests that run at once in threads make every test's code
    its process's, and nothing is watched.
11. **Watching a test** (`reads: test`): each test's `ran`, `opened` and `dirs` are its window's, the
    session's, and the ambient files up to its end; `loaded` is its test file's loading; `shared`
    its groups' runs; `everyTest` its test file and what it and the session's files require, to the
    end, since a constant is read without its code running; `imports` are the require edges and
    `opens` the open edges. Watching stops, said in `settings.watch`, when a TracePoint can't be
    enabled, or a file of the repository loads without Ruby compiling it (a compile cache).
12. **The cost**, on Ruby 3.3.6, x86-64 Linux, a suite of 300 RSpec examples in 20 files, each
    calling into two of ten library files, a `before(:context)` in a third of them; 15 interleaved
    rounds, CPU time of the RSpec process, medians: without the adapter 0.205 s, with it and
    `reads: file` 0.238 s, with `reads: test` 0.261 s: **0.08 ms a test for watching, and 27% over
    plain RSpec for both**, most of it the require and open wrappers at load.

## Consequences

- A gem whose spec_helper requires the whole library reruns every spec file when a library file
  changes, as it should: each one read it. A spec file that changes runs alone, and with
  `unit: test` only its examples whose ids are new or whose file changed.
- In a Rails app, what Zeitwerk or an initializer loaded while one test ran is every later test's,
  and with `config.eager_load` on in the test environment (Rails' default when `CI` is set),
  every file of `app/` is every test's: only changes to test files, and to what nothing loaded,
  skip anything. Keeping `eager_load` off in tests gives finer lists.
- Known misses, as RFC 0003 §3.3's and C-40's: a constant two requires away whose code never ran
  (with `reads: test`); a file added where a gem's code lists (a new fixture file under
  `fixtures :all`, a new file Zeitwerk would autoload that changes what a constant names in a
  namespace), until something loads or opens it; a file read by C code that bypasses `File` and `IO` (SQLite's database
  file, a C extension's own reads); `File.exist?` and `File.stat`, which read no content. The
  audit's second run catches them.
- `rake` and `ruby` take every Rakefile and script: one that runs neither RSpec nor Minitest
  writes nothing and is said nothing about; a Rakefile that runs pytest is no longer pytest's.

## Alternatives considered

- **Coverage.** `Coverage.result(clear: true)` per test walks every loaded file's counters, gems
  included, and `oneshot_lines` never fires again after a clear, so a file seen in one test would
  be unseen in the next; and SimpleCov takes the same Coverage, which allows one owner.
- **A global TracePoint on `call`.** One Ruby block per method call of the whole process, gems
  included: many times the cost measured here.
- **Constants as edges** (each file's constant references, resolved with `const_source_location`):
  it misses what a symbol names (`has_many :posts`) and a validation a class body declared, which
  the ambient rule covers.
- **Not loading reused spec files.** It would save their load time, but a spec file can define
  shared examples another one uses; every file loads, and the filter leaves its examples out.
